# Contract: MCP wire dialect (spec 105)

Normative framing contract for the two `McpWire` adapters and the mock
fixtures. The semantic layer (typed requests/responses) is fixed by
`lib/src/mcp/mcp_wire.dart` (spec 015/049); this document pins the bytes.

## 1. JSON-RPC envelope (both transports)

Request (generated by the adapter; ids are wire-internal):

```json
{"jsonrpc":"2.0","id":0,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"echo","arguments":{"x":1}}}
```

Successful response:

```json
{"jsonrpc":"2.0","id":1,"result":{"tools":[{"name":"echo","description":"Echoes arguments","paramsSchema":{"type":"object"}}]}}
{"jsonrpc":"2.0","id":2,"result":{"echo":{"x":1}}}
```

Application error response (→ `McpWireResponseError`):

```json
{"jsonrpc":"2.0","id":3,"error":{"code":-32601,"message":"method not found"}}
```

Notification (server → client, no id):

```json
{"jsonrpc":"2.0","method":"notifications/tools/list_changed"}
```

Field rules:
- `result` payload maps verbatim to `McpWireResponseOk.payload`.
- `error.code` (int or string) stringifies into `McpWireResponseError.code`;
  `error.message` passes through (missing → empty string).
- Responses whose `id` matches no in-flight request are dropped.
- Notifications other than `notifications/tools/list_changed` are ignored.
- Unknown methods / extra JSON-RPC fields (`params` on responses, etc.) are
  tolerated.

## 2. stdio framing (`IoStdioMcpTransport`)

- One JSON document per **newline-terminated** line on the child's stdout;
  requests are written the same way to the child's stdin. UTF-8. `\n` and
  `\r\n` both terminate a line; a trailing partial line at EOF is discarded.
- Lines that do not JSON-decode are skipped (log noise tolerance).
- stderr is drained, never parsed; retained in a bounded buffer for
  diagnostics.
- `close()` terminates the child (`Process.kill`); exit is awaited best-
  effort, never hangs close.

## 3. SSE framing (`IoSseMcpTransport`)

- `open()`: `GET {endpoint}`, headers `Accept: text/event-stream` and
  `Authorization: Bearer <token>` when configured. Status 200 opens;
  any other status → `McpWireOpenException(statusCode)`.
- Event stream: WHATWG subset — events separated by a blank line; `data:`
  fields concatenate (join `\n`, one leading space stripped); comment lines
  (`:` prefix) and `event:`/`id:`/`retry:` fields ignored; CRLF or LF line
  terminators; empty-data events dropped.
- Event `data:` payloads that decode to a JSON-RPC notification with method
  `notifications/tools/list_changed` emit `McpWireNotificationToolsChanged`.
  All other stream payloads are ignored (RPC responses ride the POST reply).
- `send()`: `POST {endpoint}`, headers `Content-Type: application/json` +
  the auth header; body = the JSON-RPC request line. 2xx + decodable body →
  Ok/Error per §1; non-2xx → `McpWireClosedException` naming the status;
  undecodable 2xx body → same exception naming the parse failure.
- `close()`: aborts the in-flight GET and closes the `HttpClient`.

## 4. Mock fixture contract (test-only, `test/mcp/_mock_stdio_mcp_server.dart`)

Invocation: `dart run test/mcp/_mock_stdio_mcp_server.dart <mode>`, modes:
`echo` | `notify` | `crash` | `garbage` (behaviors as in plan.md §3). The
mock speaks §1+§2 exactly so it doubles as a dialect conformance probe.
