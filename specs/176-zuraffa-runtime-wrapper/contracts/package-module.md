# Contract: PackageModule registration seam

**Feature**: specs/176-zuraffa-runtime-wrapper | **Date**: 2026-11-22

`PackageModule` integration is the scaffolded, optional runtime-registration
seam — not an alternative module or agent system (FR-007, plan §7.1). The
shape below is `zuraffa`'s real one, which `zfa package create` emits for you;
this contract quotes it rather than inventing a renamed wrapper around it.

## Shape (verified against `zuraffa` `master`)

From `lib/src/core/module/package_module.dart`: `PackageModule extends
ZuraffaPlugin`, and `ZuraffaPlugin` (`lib/src/core/module/zuraffa_plugin.dart`)
requires `pluginId`, `registerDependencies(ZuraffaDIContainer)`, and `routes`.

```dart
// Generated by `zfa package create` as zuraffa_agent_module.dart.
class ZuraffaAgentModule extends PackageModule {
  @override
  String get pluginId => 'zuraffa_agent';

  @override
  void registerDependencies(ZuraffaDIContainer di) =>
      registerZuraffaAgentPackage(di);   // from di/zuraffa_agent_package_registrar.dart

  @override
  Map<String, ZuraffaRouteBuilder> get routes => const {};

  @override
  List<McpTool> buildAgentTools(ZuraffaDIContainer di) => const [];
}
```

`PackageModule` also supplies `packageName` (defaults to `pluginId`) and
`zuraffaSdkConstraint`; `buildAgentTools` is where contributed tools are built,
and their names are namespaced `<packageName>.<tool>` by the framework's own
`PackageAgentTools.registerInto`. There is no `PackageModuleRegistry` type in
`zuraffa`, and this contract does not name one.

## Behavior

- Registration only wires the wrapper's runtime + ports into the host's DI
  container; it never creates a second agent loop, message format, or session
  store (FR-007).
- The wrapper's own DI (`setupDependencies(GetIt)`-style, following
  `zuraffa_permissions`) is the primary composition path; the
  `PackageModule` seam is additive and optional.
- No global agent state is introduced (plan §7.1: "Do not copy global agent
  state or add another module system merely because it exists").

## Failure modes

- Overlapping tools: the seam registers both sides and does not silently drop
  either. Which one is allowed to execute is decided at tool-call time by
  whatever governance extension is installed (#205) — not by the wrapper,
  which has no policy.
